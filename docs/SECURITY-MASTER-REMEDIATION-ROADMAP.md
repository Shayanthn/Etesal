# 🚨 SECURITY MASTER REMEDIATION ROADMAP (v5 - Action-Oriented)

این سند مرجع نهایی و تنها منبع حقیقت (Single Source of Truth) برای وضعیت امنیت پروژه است. این نسخه به‌گونه‌ای طراحی شده که تمرکز کاملاً روی **اقدامات باقیمانده و عملیاتی** باشد.

## 🛑 قوانین اجرایی (بسیار مهم برای هوش مصنوعی و مالک پروژه)
1. **قانون توقف (Zero-Trust):** هیچ کدی بدون بررسی خط‌به‌خط فایل واقعی تغییر نمی‌کند. هیچ تستی بدون خروجی واقعی تایید نمی‌شود.
2. **بستن یک تیکت (Definition of "Done"):** یک تیکت فقط در صورتی `[✅ DONE]` می‌شود که:
   - الف) AI یک یونیت‌تست نوشته و خروجی `PASS` ترمینال را ارائه دهد.
   - ب) مالک پروژه یک خروجی واقعی (SQL / curl / Console) از تست دستی ارائه دهد و AI آن را تایید کند.
3. هیچ تیکت بحرانی نباید باز بماند. یک باگ بحرانی = عدم امکان انتشار (`ABORT`).

  - **تست پس از فیکس:** اجرای `GET /rest/v1/profiles` بدون توکن باید آرایه خالی یا 401 برگرداند.

- [ ] **تیکت F-02: دستکاری موجودی کیف پول توسط کلاینت**
  - **وضعیت:** `[⚠️ PENDING FIX]`

  - **تست پس از فیکس:** تلاش کاربر عادی در کنسول مرورگر برای آپدیت `wallet_balance` باید با خطای RLS مواجه شود.

  - **تست پس از فیکس:** تزریق `<img src=x onerror=alert(1)>` در مقاله نباید باعث اجرای اسکریپت شود.

- [ ] **تیکت W-01: دور زدن فیلتر SSRF در کلودفلر ورکر**
  - **وضعیت:** `[⚠️ PENDING FIX]`

## 🕵️ فاز B: تست‌های جرم‌شناسی و زیرساخت (مسئولیت مالک پروژه)
*این تست‌ها باید توسط مالک پروژه در دیتابیس یا ترمینال اجرا شده و خروجی آن‌ها برای AI ارسال شود.*

### تست‌های SQL (ارزیابی سوءاستفاده‌های احتمالی تا امروز)
- [ ] **تست B-1: واریزهای بدون کد رهگیری (دور زدن منطق)**
  - **دستور:** `SELECT * FROM public.wallet_transactions WHERE type = 'deposit' AND (tracking_code IS NULL OR tracking_code = '');`
  - **خروجی موفقیت:** 0 ردیف.

- [ ] **تست B-2: مغایرت موجودی کیف پول**
  - **دستور:** 
    ```sql
    SELECT user_id, 
           COALESCE(SUM(CASE WHEN type IN ('deposit','gift','refund') AND status='completed' THEN amount ELSE 0 END), 0) - COALESCE(SUM(CASE WHEN type = 'purchase' AND status='completed' THEN amount ELSE 0 END), 0) AS calculated_balance_toman
    FROM public.wallet_transactions GROUP BY user_id ORDER BY calculated_balance_toman DESC;
    ```
  - **خروجی موفقیت:** 0 ردیف (یا عدم وجود مغایرت با موجودی واقعی پروفایل).

### تست‌های زیرساخت و شبکه
- [ ] **تست B-3: Rate Limiting کلودفلر (F-05)**
  - **دستور:** `for i in $(seq 1 50); do curl -s -o /dev/null -w "%{http_code}\n" -X POST https://etesal.aetherai.ir/api/validate -H "Content-Type: application/json" -d '{"url":"https://example.com"}'; done`
  - **خروجی موفقیت:** دریافت کدهای `429` پس از چند درخواست `200`.

- [ ] **تست B-4: لایه 403 (WAF)**
  - **وضعیت:** `[⛔ BLOCKED]` (نیازمند تنظیم فایروال کلودفلر توسط مالک).
  - **دستور:** `curl -I https://etesal.aetherai.ir/.env`
  - **خروجی موفقیت:** HTTP 403 Forbidden.
